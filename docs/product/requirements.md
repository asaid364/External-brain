# 产品需求

整理日期：2026-10-30。来源：本次对话中的用户陈述及 grill-me 选项。下列已确认内容不包含 AI 单方面提出的实现方案。

## 后续确认：目标驱动的周期分析与进度反馈（2026-11-05）

用户已审批目标功能实施计划：Android与Windows均可设置目标、管理完成标准、查看周期分析并手动生成；目标、用户确认和完成分析双向同步。进度按用户确认的里程碑等权计算，AI仅建议、分析方向及提供可追溯的正反馈，不自动勾选或把时长当成长。分析与事实日报分开，无记录保持未知。

每个目标由用户指定期限与回顾周期，Android在单独同意外发/费用后可自动回顾，Windows仅手动；长期未运行只自动补最近一期，较早周期手动。源记录修改/删除后保留历史衍生结论与引用标识并标失效，不额外保存原文快照；用户确认进度不会被AI自动撤回。外发许可/自动开关/密钥/付费运行状态仅本机保存，不继承日报同意。分析不增加聊天、待办、积分或系统通知权限。

本次审批授权实施及隔离合成验收，不代表功能已完成；不覆盖安装正式Android包、不访问正式数据库或既有Key、不改变网络/防火墙/系统信任，具体证据按工程状态逐步记录。该新增范围取代下文早期“阶段分析后置”的本轮边界，不改变事实日报本身的规则。

## 后续确认：安卓与 Windows 双向同步（2026-11-04）

用户已审批双向局域网实现计划：Windows 为完整离线编辑客户端，可新增、修改、软删/恢复及彻删，变化传回 Android；两端共享同一新增/编辑草稿，草稿不自动转正。普通并发由用户选择或手动整合，不能以设备时钟决定胜者；彻删为不可恢复的优先状态，对端离线时明确等待其持久确认。

Windows 独立配置 AI 并手动生成/更新事实日报，手机密钥与外发同意不复制；自动定时仍仅 Android。日报正文不直接编辑，正文并发只选完整生成候选。同步包含记录、草稿、历史、日报来源及独立问答证据，不含本机运行任务、密钥、服务冷却或 AI 配置。首次双方明确同意合并内容后才传输或传播删除；一安卓一Windows、默认不开机自启、不注册系统服务、不自动更改防火墙或系统信任。镜像同步不是独立备份。云端、备份/导出、阶段分析仍不在本轮。

以上取代下文早期“Windows/跨端规则待定”表述；审批不代表实现或实体设备验收已完成，实际进度见工程状态。

## 后续确认：原生日报（2026-11-03）

用户已确认按时间展开的客观纪实日报、次日当前手机时区00:10自动尝试、错过手动补生成、成果问题随日报产生并在查看时回答、答案先保存后统一更新、一次有界重试、仅保留最后成功正文；并授权按审阅修订方案实施。规则按主题维护：[正文与问答](../project/reports/behavior.md)、[生成与调度](../project/reports/generation.md)。第一版不直接编辑/单独删除日报，不增加真实同步、备份或阶段分析；这些后续确认优先于下文早期描述。

## 后续确认：正式安卓记录基线（2026-11-01）

用户已审阅确认记录范围、边界补充和其他一级入口呈现。正式安卓记录先推进，日报/同步本轮不开发，Windows记录后置；既定整个首版目标保留。细则按主题单独维护：[行为与草稿](../project/records/behavior.md)、[时间与时区](../project/records/time.md)、[删除与恢复](../project/records/deletion.md)、[验收](../project/records/acceptance.md)。这些确认优先于下文早期尚待决定的相关描述；跨设备删除、日报调度及正式技术栈仍待定。


## 已确认的目的

积累生活原始数据，由 AI 分析是否存在自我提升、停滞和重复问题。由用户确定重视的方向，首先关注能力与成果。首轮验证最重要的价值是发现一个用户原先没注意到的重复问题，并据此改变行动。

先由用户自己使用验证，之后希望开放给其他人。

## 已确认的记录与日报行为

- 安卓手机随时自由输入，覆盖工作、学习、休息、娱乐和生活事务等重要活动。
- 第一版仅文字，之后增加语音。
- 计划作为自由文字保存，不做专门待办管理。
- 先自由记录一周，AI 提出可能关注的能力，由用户确认。日报不评价成长。
- 缺少关键结果时追问；晚上集中询问最重要的 1—3 个问题。
- 每天定时生成日报草稿，用户补充后更新；日报只整理事实。
- 原始记录保留发生时间、录入时间和修改历史，分析默认使用修正后的内容。
- 日报与原始数据保存到电脑。

## 已确认的阶段分析

- 期限由用户设定，到期后统一分析，不能擅自设成固定周报或月报。
- 分析关注用户确认的能力与成果变化，支持识别重复问题。
- 证据不足时建议延长观察期，由用户决定是否继续积累。
- 与用户讨论后形成下一阶段行动计划，不自动将建议记为用户承诺。

## 已确认的平台和存储

- 手机端：安卓；电脑端首期：Windows。
- 用户最终可选择云端保存或仅本地保存，两种模式是预期产品范围。
- 本地模式在手机与电脑处于同一局域网时自动同步；电脑不在线则等待。
- 每位用户填写自己的服务地址、API Key 和模型，承担自己的调用费用；希望兼容官方 API 和中转站。
- 计划使用 OMP 开发，期望 Gemini 3.7 Flash 负责 UI。尚未验证工具和模型是否可用。

## 已确认的交付顺序

用户选择尽快交付小版本开始积累数据，再补齐功能。最早可用版本包括：安卓文字记录、本地保存、AI 日报、Windows 局域网自动同步。云端与阶段分析后续补齐；不是删除原有双存储模式需求。

## 实现建议，尚待验证

- 两页手机可操作原型先验证记录与日报体验。
- 报告引用原始记录；AI 衍生内容与原始数据分开保存。
- 电脑端导出 Markdown 日报与 JSON 原始数据。
- 安卓后台受系统调度限制，定时日报需要补执行与状态提示。

## 待确认

- 正式名称、技术栈、开发期限、预算、首轮观察期限。
- OMP 的具体项目、版本、多 Agent 能力及配置方式；Gemini 的确切模型 ID、接口和可用性。
- 首个版本的服务商兼容范围、日报生成时间、日期边界与错过执行后的行为。
- Windows 配对、身份校验、数据格式、冲突处理与用户删除数据的规则。
- API Key 的存放方式；云端模式的部署、账号与隔离方式。
- 数据修改后是否自动更新旧日报、分析版本如何保留。
