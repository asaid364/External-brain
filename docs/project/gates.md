# 项目门禁

更新：2026-10-31。

本文件将已有授权、协作和验证规则整理为可检查的放行条件，不增加产品功能或自动化审批系统。门禁是文档检查表，未实现CI。具体结果见 [验收标准](acceptance.md)，执行项见 [任务清单](tasks/README.md)。

## 状态与证据

每道门禁记录：适用任务/版本、检查人或角色、检查日期、证据位置、结论（通过/未通过/待验证/不适用）及限制。不适用须写明原因，不代表通过。没有证据不自动放行；本文不为整个项目预填通过。

## G1：开工与范围

- 条件：当前任务已授权；读过项目入口、需求和状态；能区分确认需求、建议与待定事项；明确修改文件和交付目标。
- 阻断：范围含糊导致实质不同的产品决策、未授权破坏操作、需要读取无关个人资料。
- 处理：只暂停受影响部分，先查文档与工具；仍不可得再询问用户，不借此扩大范围。

## G2：技术决定与设计协作

- 条件：新增框架/依赖有依据；正式应用关键未决项在相关实现前落实。UI 任务核实 OMP 当前设计角色入口及配置，明确主 Agent、Designer 和文件所有权。
- 阻断：无法调用要求参与的设计角色、拟覆盖其模型、公共组件存在同时编辑风险，或必须依赖尚未确认的技术/协议决定。
- 处理：报告具体阻塞；可继续独立的资料或技术准备，不替换角色冒充完成。
- 不适用：纯文档迁移无需发起 UI 设计调用。

## G3：数据、安全与实现

- 条件：符合 [禁止项](prohibitions.md)；原始与衍生数据分开，时间与历史保留；失败不误报成功；模型、网络与同步模拟均明确标记。
- 阻断：秘密/真实资料进入演示、数据丢失或手动内容静默覆盖风险、虚假同步或保存提示。
- 处理：先消除受影响风险再验收；不得用隐藏错误代替修复。

## G4：原型交付

- 条件：原型适用验收项有实际浏览器操作证据；构建与类型检查通过；源码、锁文件、启动、当前局域网访问方法及存储限制说明齐全。
- 原型桌面交付与真实安卓验收分别记录。无真实设备证据时可以交付代码及桌面结果，但不能声称手机可达、输入法或触摸已通过。
- 阻断：主要路径未运行、缺少可运行代码、失败保存丢字或重复创建、未处理持久化失败、手动修改保护缺失。

## G5：正式首版放行

- 条件：真实安卓记录/本地保存、真实 AI 日报、真实 Windows 局域网同步均按适用标准完成；跨设备及失败恢复证据齐全；必要协议与安全决定已确认。
- 阻断：仅有浏览器模拟、仅电脑自访问、关键功能待开发、用图谱/测试替代真实链路证明。
- 当前事实：安卓记录与日报代码、本地构建及分层测试已交付，真实AI服务、实际后台调度与实体手机完整验收未放行；同步待开发。日报证据见 [DR清单与实际结果](reports/acceptance.md)，不能按受控模型测试或MCP连接结果放行。

正式安卓记录阶段按 [R01—R21](records/acceptance.md) 独立验收：真实安装运行及本机保存、草稿、历史、删除、时区与失败恢复须有证据；合成演示与真实记录隔离。阶段通过不放行真实AI或同步；需求确认不等于实现或实机验证通过。


## G6：阶段分析与后续能力

- 条件：用户已确认观察期限和关注能力，阶段结论有来源，证据不足有明确表达；云端/多用户/语音按当次授权和确认方案另行验收。
- 阻断：替用户决定期限或承诺、证据不足却断言成长、把未来能力当现有能力。

## G7：完成记录与发布授权

- 条件：报告修改、实际验证及限制；更新任务状态与相关开发说明；文档迁移无失效引用。
- Git 提交、远程推送和环境安全设置变更分别需要授权，不因其他门禁通过而自动获准。
- 检查未通过则不标记对应任务完成，不影响已证实完成的独立任务。
